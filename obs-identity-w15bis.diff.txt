# FDB / LLDP — implementazione iniziale passiva (read-only)

**Stato:** requisito vincolante per wave futura (post W1.5-bis / writers SNMP).  
**Non** interrompe W1.5-bis. **Nessun** codice writer in questa nota.  
**Allineamento:** sblocca misure per `DEBT-E3-AVAILABLE-FALSE`; ortogonale a identity (`identity_evidence`).

---

## 1. Semantica (vincolante)

| Segnale | È | Non è |
|---------|----|--------|
| **FDB** (MAC + switch + porta + VLAN/bridge-domain + timestamp/age) | Evidenza di **presenza / posizione L2** | Identità chassis; **ownership** del MAC |
| **LLDP / CDP** | Corroborante topologico (neighbor dichiara) | Prova di ownership; affidabile contro spoof |

- FDB **non** prova ownership.
- LLDP/CDP è **solo corroborante** e **potenzialmente spoofabile**.
- Nessuna fusione identity / `chassis_id` / `Asset.name` da soli questi segnali.
- Scala E0–E5 identity: FDB-only resta sotto E5-bridge; LLDP subtype deve restare vincolato (vedi `obs-currency-identity-evidence.md`).

---

## 2. Target switch (LGS310C / LGS328C) — accesso SNMP

Preferenza e minimi di sicurezza (config switch + collector):

1. **SNMPv3 `authPriv`** (non community v2c in prod).
2. Utente **sola lettura** (GET/WALK; **nessun SET** nel codice né nei diritti).
3. **ACL** sorgente: solo IP di **Cassiopea** (collector).
4. **View** limitata alle MIB necessarie: Bridge (FDB), LLDP (e CDP solo se già esposto e utile), ENTITY (serial/chassis fisico). Niente view “tutto”.
5. **Segreti** solo env/secret store — **fuori** repo, log, DB, UI, report exchange.
6. **Timeout** e **rate limit** sul poll (non martellare; backoff su failure).
7. **Non abilitare** LLDP/CDP su porte dove non serve (rumore + superficie spoof).

Riferimento stile credenziali (NAS, non switch): [`ASUSTOR_SNMP.md`](ASUSTOR_SNMP.md) — stesso principio “RO + env-only”.

---

## 3. ObservationRaw — contratto minimo

Ogni riga FDB/LLDP (o fallimento di poll) deve poter esprimere:

| Campo | Ruolo |
|-------|--------|
| `switch_id` | Switch osservatore |
| `port` | Porta / ifIndex risolto |
| `VLAN` / bridge-domain | Contesto L2 |
| `timestamp` | Quando acquisito |
| `age` / `last_seen` | Freschezza sulla tabella bridge (se esposta) |
| `acquisition_method` | es. `snmp_v3_authpriv_walk` |
| `failure_state` | ok / timeout / auth / acl / view / parse — **mai** silenzio su poll fallito |

**Dedupe:** per **transizione** di binding (MAC↔porta↔VLAN o comparsa/scomparsa), **non** per ogni poll uguale. Poll ripetuto senza cambio → no flood di raw.

---

## 4. Alert «nuovo MAC su access port»

1. Solo **dopo** classificazione porta **misurata**: `access` / `trunk` / `uplink` / `AP` / `powerline` (no euristica inventata).
2. Fase iniziale: **solo informativo** (finding / evento).
3. **Vietato:** quarantena automatica, port shutdown, ACL auto, “isolate”.

---

## 5. Minacce e limiti onesti

Prevedere esplicitamente (doc + detector, non finger-wagging):

| Scenario | Nota |
|----------|------|
| Spoof MAC | FDB/LLDP possono mentire |
| MAC move | Transizione legittima vs hop sospetto — distinguere con storia, non panic |
| CAM flood | Tabella piena → evidenza degradata; failure_state / coverage |
| Randomized / LAA MAC | Non trattare come identità stabile |

**Assenza di alert ≠ sicurezza.** Un silenzio (poll down, view vuota, timeout) è **failure**, non “rete pulita”.

---

## 6. Fuori scope di questa wave iniziale

- Writers identity / confirm_link automatico.
- SET SNMP, trap-driven enforcement.
- Quarantena / shutdown porte.
- Abilitare LLDP/CDP “ovunque” per completezza.

## 7. Ripresa

Coda OBS-CURRENCY dopo chiusura W1.5-bis e review writers (W2+ / presenza W7 secondo piano vigente). Debito traccia: **DEBT-FDB-LLDP-PASSIVE** in `KNOWN_DEBT.md`.

# Policy MAC↔IP (dominio Michele, 2026-07-25)

**Stato:** contratto + classifier puro in `api/app/services/mac_ip_policy.py`.  
**Wiring** in inventory/trust reconcile → **prossima wave presence** (OBS-CURRENCY **W7** topologia/presence/scans, post chiusura W1.5-bis).  
**Non** è una scorciatoia di fusione chassis.

## Regole

1. Un apparato **normale** e **current** si riconcilia a uno **chassis con ≥1 IP corrente**. Non serve che ogni MAC/NIC abbia IP.
2. **Eccezione:** powerline / Fritz 510E (e classi afini esplicite) possono essere legittimamente **L2-only** (`l2_only_allowed`).
3. MAC con sola storia, **nessuna** osservazione L2 fresca, **nessun** IP corrente sul chassis → non può essere `present`/`current` → `stale` o `superseded`.
4. MAC **FDB-fresh** senza IP → stato distinto **`present_l2_unaddressed`**; cercare management IP del chassis (misurato); **non inventare** identità.
5. Un nuovo binding MAC↔IP **corrente** **supersede** / storicizza il vecchio.
